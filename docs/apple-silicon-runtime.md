# Native developer launcher

Use native ARM64 macOS with Docker Desktop running. Install native `uv`, Bun 1.2.18, native Node.js compatible with Next 16 (tested Node 22), Ollama, FFmpeg and ffprobe with VideoToolbox. From the repository root:

```sh
./scripts/mac.sh doctor
./scripts/mac.sh setup
./scripts/mac.sh start
./scripts/mac.sh status
./scripts/mac.sh stop
```

Open http://127.0.0.1:3000. `start` builds and runs the optimized production website in `.next-production`. Use `start --dev` explicitly for hot-reloading development; `.next` remains separate. Production startup rebuilds before opening the web listener, and rolls back owned services if the build fails. Setup uses managed ARM64 Python 3.11, separate service virtual environments and committed native dependency locks. It preserves existing environment files. Database/Redis infrastructure runs in the isolated `opencut-mac` Docker project; AI workers, backend, web and a private Ollama instance run natively. Setup/start accept `--with-turboquant` for the optional service.

Listeners bind to loopback. Ports: web 3000, backend 8420, workers 8421–8427, optional media 8428, optional TurboQuant 8430, owned Ollama proxy 11435/upstream 11436, database 5432, Redis 6380 and Redis HTTP 8079. Existing Ollama on 11434 is left alone. Incompatible executables, missing dependencies, occupied ports and failed health checks prevent startup. Logs/state/models are in ignored `.mac-runtime`.

Stop verifies recorded process identity and only terminates launcher-owned processes and descendants. It stops this Docker project without removing persistent volumes. The old image-only entry point delegates to the supervisor.

This launcher is the first part of a draft Apple Silicon stack. Subsequent PRs add MLX transcription, cross-process memory coordination, native media jobs and measured validation. Read `docs/apple-silicon.md` in the completed stack before enabling experimental acceleration. Desktop packaging is not included.

The native profile overrides connection URLs in process memory to use its own local PostgreSQL/Redis and site origin. Environment files stay intact. A fresh managed PostgreSQL database receives the repository schema; an unknown or changed existing schema requires a reviewed migration instead of an automatic schema push. Project serialization formats are unchanged.


## Protecting local editing projects

Projects and imported originals are kept in this browser profile, using IndexedDB and origin-private storage. Use the same browser and `http://127.0.0.1:3000` each time: `localhost`, a different port, or another browser has separate storage. Database Docker volumes do not contain these browser-local projects. Clearing site data or deleting the profile removes local projects/media.

In editor Settings, choose **Download project backup**. Keep the `.ocbackup` file on disk outside browser storage. It includes current timeline/settings and original imported media, with SHA-256 checks of the manifest and each 8 MiB media chunk. Proxies, decoded caches, version-control history and API keys are excluded. The current archive format supports projects up to 8 GiB of original media with a 16 MiB manifest; larger projects need a future streaming archive implementation. Do not clear browser data until you have verified a restore.

Choose **Restore project backup** in Settings or the Projects page, select the downloaded archive, and wait for a new `(restored)` project. The entire archive is validated before storage writes, media is written before project registration, and incomplete restores attempt to remove their staged media. Restore uses a fresh project ID and preserves existing projects. Future project versions are rejected rather than loaded unsafely; use the app version that created the backup. A failed restore leaves its source archive unchanged.

A project can be edited in one tab at a time. A second tab displays a retry screen; close the first editor, then retry. Browser Web Locks release ownership when the tab closes or crashes. Saves and media mutations respect ownership, including operations launched from the Projects page. Use a desktop browser with Web Locks support; the app refuses unsafe concurrent editing when locking is unavailable.


If an original file disappears from browser storage, project loading now stops and lists the missing names and byte counts. Choose **Reconnect original files** and select those originals; matching files are copied into the existing media IDs, preserving timeline edits. Filename and size are matching checks, not a content-authenticity guarantee: select your actual original files. If metadata is missing too, restore a project backup. Invalid project URLs offer retry, backup restore, and return to Projects without creating replacement projects.


For reproducible audio timing checks, generate a nonperiodic fixture with `python scripts/mac/prepare_audio_markers.py --output /tmp/stereo-markers-4s.wav` (NumPy required). Import it in a new project, add it to an audio track, split at 00:00:02:00, and export MP4 with audio enabled. Run `python scripts/mac/validate_audio.py --reference /tmp/stereo-markers-4s.wav --encoded /path/to/export.mp4 --markers 0.25 1.25 1.99 2.5 3.75 --report /tmp/audio-report.json`. It preserves presentation timestamps, checks both channels, and fails for missing/weak matches or offsets beyond 20ms. Raw PCM decoded without the initial presentation offset can give false timing diagnoses; periodic tones alone cannot establish alignment.

Export Cancel stops pending work and shows **Cancelling…** until cleanup finishes. Closing the export popup also requests cancellation; reopening it keeps the pending job visible and prevents overlapping exports. Browser audio decode/offline rendering cannot be interrupted mid-call, so those stages finish before ownership is released. After cancellation, export options are available for retry and no result is downloaded.

Project deletion requires typing the exact text `DELETE`. The app waits for an active autosave before deleting and clears queued save work to prevent resurrection. Deletion is permanent: create and verify a portable backup first. Failed new-project persistence leaves the previous project active so creation can be retried.


## Runtime readiness and recovery

`./scripts/mac.sh status` probes identity-verified processes and actual Docker container health. It returns exit code 0 only when the complete configured stack is healthy; missing/stopped/unhealthy services return 3. Use `./scripts/mac.sh status --json` for automation. Status can run during startup/restart without acquiring the supervisor mutation lock, and does not create a new runtime token. The report includes the recovery command and log directory, never the token.

Use `./scripts/mac.sh restart` after a stopped worker or failed service. It stops only identity-verified launcher-owned processes and the isolated Compose project, then rebuilds and starts the production site. Existing database volumes and browser-local projects remain; it does not delete browser storage. `restart --dev` explicitly uses the development web server. This is explicit recovery, not automatic process respawn. Inspect `.mac-runtime/logs/<service>.log` for the failure cause. Invalid process-state JSON is preserved and rejected rather than guessing which processes to terminate.

Native workers and backend accept browser requests only from the editor origins `http://127.0.0.1:3000` and `http://localhost:3000`, and require a loopback Host header matching the listening port. Unrelated cross-site subresources and WebSocket origins are rejected before model admission. Local server-to-server calls without a browser Origin still work. The media worker retains its separate launcher-token requirement. These checks protect the browser-to-native boundary; they do not authenticate other processes running as the local user. Container entrypoints retain their configured deployment behavior.

Restore validates the whole archive before storage writes and creates a new project only after all originals are stored. A failed write attempts to remove staged media and leaves existing projects intact. If cleanup also fails, the error explicitly reports incomplete restore data; keep the backup and retry after resolving storage access/capacity. A durable restore journal now tracks staged destinations. Loading the project list retries cleanup for abandoned restores, skips a restore still running in another tab, and preserves every published project. Failed cleanup keeps its journal entry and reports an error so it can retry later. Actual browser/process termination during OPFS writes still requires acceptance validation.

Run `./scripts/mac/test-linux.sh` with Docker running to reproduce the lightweight x86-64 Linux native regression job. It uses a digest-pinned official Python image, installs the separate tests.lock, and mounts only scripts/mac read-only. It does not start model services or mount browser projects, environment files or database volumes. On an M-series Mac, Docker emulates x86-64; this does not substitute for the full GitHub build matrix.

The native website also checks Host and browser Origin before pages, API routes and static resources. Only loopback hosts on port 3000 are accepted; unrelated cross-site subresources and forms are denied. External links may navigate to the editor with GET. Requests rejected by this guard return 403 with no-store; ordinary non-native deployments do not enable it. Reproduce the read-only live check with `python scripts/mac/validate_web_access.py --report /tmp/web-access.json`. This is a browser boundary, not authentication of local processes or a complete security review.

The 48 kHz FLAC timing fixture uses the same six-marker hold-boundary source without speed automation: generate `prepare_audio_markers.py --hold-boundary --output /tmp/markers.wav`, then `ffmpeg -i /tmp/markers.wav -ar 48000 -c:a flac /tmp/markers.flac`. For a four-second export, run `validate_audio.py --reference /tmp/markers.flac --encoded /path/to/export.mp4 --markers .25 .99 1.25 1.99 2.5 3.75 --report /tmp/flac-timing.json`. The measured browser export resamples to stereo 44.1 kHz AAC; the portable project backup retains the original FLAC bytes.

Portable archives support up to 32 nested compound clips and 256 levels of nested scene metadata. Deeper archives fail validation before restore writes; flatten excessive nesting in the source project before creating its backup. These limits supplement the archive size and identity/reference checks.

## Upgrading and returning to a previous revision

This procedure is a recovery runbook; a full cross-version upgrade/rollback rehearsal remains a release gate. Do not treat a successful rebuild as proof that an older application can read data saved by a newer one.

1. In the running editor, wait for **Saved**, download a portable backup of each project, and verify a restore as a separate project. Keep the pre-upgrade archives unchanged. Use the same browser profile and `http://127.0.0.1:3000` throughout. Export important finished videos separately; archives exclude version history and API keys.
2. Record the current commit (`git rev-parse HEAD`), `./scripts/mac.sh status --json`, and the candidate commit outside browser storage. Check `git status --short`; preserve local changes before switching revisions. Review project-format migrations, database schema changes, native locks and release notes between the two commits. A schema change needs an explicit migration/recovery plan.
3. If server accounts/sharing/version-control data matter, also back up PostgreSQL while the current stack is healthy. For the managed native database, `docker compose -p opencut-mac -f .mac-runtime/compose.json exec -T db pg_dump -U opencut -d opencut --format=custom > /absolute/path/native-db.dump` produces a server-data archive. Check command success and a nonempty file, and verify it in an isolated database before relying on it. This dump does not contain browser projects or imported originals. Keep environment files and credentials private and separately protected.
4. Stop with `./scripts/mac.sh stop`, switch to the exact reviewed candidate commit, install its frozen JavaScript dependencies (`bun install --frozen-lockfile`), and run `./scripts/mac.sh setup` for its native locks. Setup preserves existing environment files. Start with `./scripts/mac.sh start`; wait for `./scripts/mac.sh status --json` to report ready. If an existing database schema is rejected, stop and review the migration; do not overwrite the schema marker or force a schema push.
5. Reopen the editor and verify representative projects, originals, saved edits, playback and a downloaded export. Keep the prior commit and pre-upgrade backups until the new revision has completed the stability/recovery gates.

If the candidate fails, stop its owned stack and return to the recorded known-good commit with a clean checkout; reinstall that revision's frozen dependencies/native locks and start it again. Never use a hard reset to discard unpreserved work. Keep `.mac-runtime`, database volumes and browser site data intact. The launcher does not automatically roll back source, dependencies, database migrations or browser migrations. If a project was upgraded to a format the previous app cannot read, use its unchanged pre-upgrade backup with a compatible application revision; a post-upgrade backup is not a downgrade conversion. A database migration likewise needs its reviewed reverse migration or verified server-data restore. Do not delete volumes or clear browser data to bypass a compatibility error.

To rehearse server-data backup without restoring over the live database, run `python scripts/mac/validate_database_backup.py --report /tmp/database-recovery.json` using the native backend environment. It dumps the live native database into mode-0600 files under private `.mac-runtime/validation`, uses the exact running PostgreSQL image ID in a temporary container with no network/ports and tmpfs data, compares restored schema and public-table row digests, and exercises three synthetic typed rows in a second temporary database. Only the disposable instance receives restore/probe writes; it is removed afterward. Private dumps remain for recovery and must not be committed or shared. Concurrent source writes may conservatively fail the comparison. The measured native database contained 15 tables and zero rows; synthetic recovery passed, but populated application workflows and cross-version migrations still require validation.

`soak.py` is a native-services workload, not the complete editor stability test. Its report separates native_checks_passed from full_stability_acceptance_passed; the latter (and legacy passed) remain false because browser editing, GPU memory, defined post-warm-up swap and sustained allocation growth are not measured by this script. Do not promote a native-only report into a full release acceptance result.

For an isolated frontend CI check, first pull the official x86-64 image with `docker pull --platform linux/amd64 node:22-bookworm`, then run `./scripts/mac/test-web-linux.sh`. The runner archives committed HEAD (uncommitted changes are excluded), resolves the local image ID, and runs Bun 1.2.18 frozen installation, the production website build and root tests with workflow placeholder settings. Only the source archive is mounted read-only; installed dependencies/build output stay in the disposable container. It needs registry access and up to 6GiB of container memory. Successful local Docker execution would still not substitute for the GitHub Windows/macOS/Linux matrix. At introduction, only shell syntax has been checked; execution is pending the image download.

The frontend runner also accepts `OPENCUT_CI_NODE_IMAGE=node:22-bookworm-slim` after pulling that official variant for linux/amd64. On macOS it selects the system Git before Intel-only executables that may exist in /usr/local/bin. The first actual invocation exposed that host PATH issue before container creation; the corrected runner entered the x86-64 slim container and reached npm installation. At this point dependency installation/build/test execution is still in progress; no Linux frontend pass has been established.

The isolated Linux frontend runner has now completed successfully for committed source 20bd157 with the slim image: Node 22.23.3, Bun 1.2.18, frozen installation, production build/TypeScript and 248 tests. See linux-frontend-ci-validation.json; this is local x86-64 Docker emulation, not the hosted OS matrix.

To reproduce the deployed native cancellation probe with the prepared 60-second 4K test fixture, run `python scripts/mac/validate_media_cancellation.py --report /tmp/media-cancellation.json` in the native backend environment. It uploads only that fixture, starts three bounded jobs, cancels running/queued test jobs, checks in-use asset protection and following-job download, then releases its input. Completed output uses the worker’s normal expiry. Encoder monitoring matches the resolved FFmpeg executable and samples every 10ms; it supplements coroutine ownership tests and does not establish browser parity or full-session stability.

Native temporary-media expiry runs once a minute for inactive entries older than one hour. A failed unlink is logged and retained for retry on the next sweep; it does not stop cleanup of other entries. Inputs owned by queued/running jobs and recent outputs are preserved. Storage limits still apply while a deletion remains unsuccessful.

The native CI reproduction now includes 41 native logic tests and 15 media worker tests. In addition to scripts/mac, it mounts only services/media-service/app.py and test_media.py read-only, and installs their lightweight HTTP/validation dependencies from tests.lock. No service environment, token, model or browser project directory is mounted. The combined 56-test x86-64 Linux run passes; media subprocess/failure injection tests supplement the separate live VideoToolbox cancellation probe.

## Isolated browser storage tests

Start the production website on `http://127.0.0.1:3000` first. From the repository root, run `bun install --frozen-lockfile`, export `PLAYWRIGHT_BROWSERS_PATH="$PWD/.mac-runtime/playwright"`, then run `bun x --no-install playwright install chromium`, `bun run test:browser:types`, and `bun run test:browser`. The pinned test tool uses full Chromium in headless mode with a fresh context for every case; it does not attach to your browser or use your profile. All backups/originals are synthetic fixtures. Reports, traces, screenshots and installed test browsers stay in ignored runtime storage.

Nine production-UI tests currently pass: durable restore/reload and byte-preserving backup, malformed-reference rejection, real write-quota failure with journal/OPFS cleanup and retry, missing-original detection/reconnect, actual renderer-crash recovery after a staged original commits, cross-tab editor exclusion/recovery, downloaded video frame/duration/color inspection, split/undo/redo/save/reopen persistence, and file-picker import with original-byte preservation after reload. The quota test changes only its isolated context's effective Chromium quota; its navigator estimate remains optimistic, exercising actual write/cleanup failure rather than the separately unit-tested admission check. The test dismisses first-run onboarding through its visible Close control. The crash test reopens a page in the same browser context and verifies abandoned-journal cleanup, original-byte preservation and retry. These tests do not establish whole-browser termination or power-loss recovery, large-project reliability, codec/effect parity or the 30-minute editing/AI gate. Local runs use the running production server. Install FFmpeg/FFprobe on PATH (or set FFMPEG/FFPROBE). Linux CI installs Chromium plus media inspection tools and sets OPENCUT_BROWSER_START_SERVER=1 to start the production build for the test duration; it refuses to reuse an occupied port. Failure reports/traces/screenshots are retained for seven days. Both Linux hosted eight-case browser jobs pass on publication 4864985; the ninth import case is verified locally and awaits publication.


## Opt-in sustained editing session

The normal browser suite skips `session-soak.pw.ts`. On the native Mac stack, prepare a 120-second 1080p mixed-media backup with `services/ai-backend/.venv/bin/python tests/browser/prepare-session-fixture.py --template /absolute/path/mixed-media-fixture.ocbackup --video /absolute/path/video-1080p-120s.mp4 --output .mac-runtime/fixtures/session-1080p-120s.ocbackup`. The template supplies the validated image/audio originals; the video fixture must be 120 seconds at 1920x1080. The generator verifies the source archive manifest/media hashes before replacing its video.

Run with `OPENCUT_SESSION_BACKUP="$PWD/.mac-runtime/fixtures/session-1080p-120s.ocbackup" OPENCUT_SESSION_SOAK_MINUTES=30 OPENCUT_SESSION_WARMUP_MINUTES=2 PLAYWRIGHT_BROWSERS_PATH="$PWD/.mac-runtime/playwright" bun run test:browser --grep 'sustained mixed'`. The local production stack, cached Whisper/Ollama/image models and ten-minute speech fixture are required. Override the speech path with OPENCUT_SESSION_SPEECH. This sends real requests to loopback native services and may report model admission failures under memory pressure. It never selects a smaller model silently.

Each cycle operates visible playback, split/undo, export/download, backup/save and reload. The Python sampler uses the backend environment's psutil and records descendant browser/GPU-process RSS, native-service process RSS and host swap. Warm-up is excluded from swap growth. Process RSS may double-count shared pages and does not establish independent GPU allocation, audible output quality or full parity; the report retains `full_stability_acceptance_passed=false`. Short runs cannot pass the 30-minute criteria. Do not rebuild/restart the stack or launch another browser suite with the same output directory during the run. Reports and memory samples remain in the ignored browser-test output directory; preserve them before a later run clears that directory.
